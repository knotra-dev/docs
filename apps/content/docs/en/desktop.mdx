These screens use **My first pipeline**, the two-block greeting from [First steps](/docs/getting-started). Open that lesson if your workspace is empty.

## Build and configure

1. Click **Pipelines** in the left sidebar, then open your pipeline.
2. Click a block on the canvas. Edit its **Instructions** in the panel on the right, then click outside the field to apply.
3. For a model block, choose its **Source** and **Model**. Each block keeps its own choice.
4. Click **Save** in the editor header.

<DocScreenshot src="/images/beginner-06-model.webp" width={340} height={717} alt="Answer block settings with Instructions, Source, and Model" caption="Select a block to edit it. Source and Model are below Instructions." />

Connect an output to an input by clicking the output's small circle, then the input's circle. The line passes that value to the next block.

<DocScreenshot src="/images/beginner-04-connect.webp" width={660} height={253} alt="The Answer text output connected to the Human draft input" caption="The greeting leaves Answer through text and enters Human through draft." />

**Canvas**, **Code**, and **Files** show the same pipeline package. Click **Workflow** for pipeline-wide inputs and outputs. Click **Resources** in the sidebar to inspect connections and use a block's **Set up** action. [Choose block connections](/docs/guides/block-connections) covers tools and code environments.

## Follow and review

### Start a run

1. Open your pipeline and click **Run** at the top right.
2. In **Run on engine**, check the **Engine profile** and **Workflow values (JSON)**.
3. Click **Start run**. The app opens the run so you can follow its progress.

If the header says **Local engine**, click it first. In Settings, keep Docker running and choose **Start local engine**. Wait for **Running**, then reopen the pipeline from the left sidebar. [Model setup](/docs/guides/connect-models) covers saving a source first.

<DocScreenshot src="/images/beginner-08-run.webp" width={610} height={580} alt="Run on engine dialog with Engine profile, workflow input JSON, and Start run" caption="Run opens this dialog. Start run begins the work." />

### Answer a review

1. Click **Inbox** in the sidebar and choose the request for your run.
2. Read **What to do** and **From previous steps**.
3. Complete the response fields, then click **Submit response**.

<DocScreenshot src="/images/beginner-09-reply.webp" height={1000} alt="My first pipeline review request with the greeting and Your answer field" caption="This greeting lesson needs a text reply. Other pipelines can ask for approval or different fields." />

### Read the result

1. Click **Runs** and open the run with your pipeline's name.
2. Wait for **Completed**, then click **Outputs**.
3. For the greeting lesson, read **values → answer**. It returns text, so there is no file to export.

<DocScreenshot src="/images/beginner-10-result.webp" width={1218} height={410} alt="Completed greeting run with its answer in the Outputs tab" caption="Each run keeps its own inputs, progress, and outputs." />

To inspect progress, open **Live graph** and click a block. Use its **Activity** or **Data** tab; **Timeline** shows pipeline activity, and **Replay** explores saved history. Execution IDs are in **Technical details** when you need them.

## Explore the areas

For a pipeline that creates files, click **Artifacts**, select the file's card, then click **Export** in its right-hand preview. [Review an announcement](/docs/guides/first-workflow) walks through a workflow that creates `publication.md`.

<details>
<summary>Templates, Settings, and saved work</summary>

- **New pipeline → Ready to run** opens optional templates. **Settings → Learn to use Knotra → Restart tour** reopens the learning pipeline and keeps your edits.
- **Settings** contains model providers, MCP servers, the local engine, existing-engine connection, assistant MCP control, appearance, and backups.
- Sources and pipeline choices persist across restarts. Credentials are excluded from workspace backups. Connection changes apply when unfinished runs complete, including human waits and paused runs.
- Inbox forms follow each request's schema. Use **Advanced JSON** for complex custom responses.

</details>
