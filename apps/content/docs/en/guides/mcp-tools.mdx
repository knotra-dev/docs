**Connect once. Enable tools. Grant them to a block.** This lets a pipeline call an external service. To let an assistant edit Knotra itself, use [Control Knotra with MCP](/docs/guides/control-knotra).

## Connect and choose allowed tools

1. Click **Settings** at the bottom left, then **MCP servers → Add server**.
2. Enter a **Server name** and your service's **MCP server URL**. Use HTTPS, or HTTP on localhost. URL parameters, fragments, and embedded credentials are unsupported.
3. If required, enter an **Access token** without the `Bearer` prefix.
4. Click **Connect and load tools**. Under **Enabled tools**, check only the tools to allow.
5. Click **Save server**.

<DocScreenshot src="/images/mcp-tools.webp" width={1000} height={747} alt="MCP server form with Research library, an example MCP endpoint, Search documents checked, and Read document unchecked" caption="Settings → MCP servers. The Research library name and example.test URL are illustrative; enter your real server endpoint." />

**Check:** your server appears in the saved list with its enabled-tool count.

Discovery does not execute tools. New tools start **disabled**. Tokens stay in the operating system credential store and are excluded from workspace backups.

<details>
<summary>Supported connections and token changes</summary>

The native form supports HTTP MCP endpoints with an optional bearer token. Local command/stdio servers require an engine profile; browser OAuth sign-in is not supported in this form.

Names, endpoints, catalogs, and enabled tools survive restarts. When editing a token, leave it blank to keep it, enter a replacement, or choose **Remove saved token**. After changing the URL, explicitly re-enter or remove its token before connecting to the new address.

</details>

## Call a tool from a block

1. Return to your pipeline and click a **Tool** block.
2. In the right panel, choose **MCP server**, then **Tool name**. Only enabled tools appear.
3. Under **Tool arguments**, choose **Enter values**. Fill the displayed fields; for the pictured **Search documents** tool, type your search in **query**.

<DocScreenshot src="/images/guide-tool-block.webp" width={340} height={877} alt="Tool block settings showing Research library, Search documents, and the tool argument form" caption="Tool block → MCP server → Tool name → Tool arguments. This example uses Search documents." />

**Check:** the form matches the selected tool. Connect its result to the next block or a workflow output.

<details>
<summary>Complex arguments, result formats, and switching tools</summary>

Simple object schemas have labeled fields; complex custom arguments remain in advanced configuration. To pass this block's inputs, choose **Use block inputs (CEL)** under **Tool arguments** and supply an expression. You do not need server or tool IDs.

New blocks use the tool's advertised structured result schema, or an array of content blocks when none is advertised. Custom output definitions are preserved. **Use tool response format** explicitly adopts the selected tool's format; check downstream bindings after changing an existing result's shape.

When switching tools, Knotra lists saved fields the new tool cannot accept. Review **Remove unsupported fields** before using it; compatible values are kept.

</details>

## Give an agent selected tools

1. Click an **AI agent** block in your pipeline.
2. In its right panel, find **MCP tools**.
3. Under your server's name, check the individual tools this agent may use.

<DocScreenshot src="/images/guide-agent-permissions.webp" width={340} height={877} alt="AI agent settings showing individual MCP tool grants" caption="AI agent → MCP tools. Check only the tools this agent needs." />

**Check:** the required tool is checked in this block. The agent decides when to call it. Enabling tools in Settings does not grant them to every agent.

## Change a server safely

1. Open **Settings → MCP servers** and find the saved server.
2. To edit, click the **server name**. To reload its catalog, click the **circular-arrow button** on the right. The **trash button** removes the connection.

<DocScreenshot src="/images/guide-mcp-manage.webp" width={1000} height={171} alt="Saved Research library MCP server with its clickable name, circular-arrow refresh button, and trash remove button" caption="Click the server name to edit; the right-side arrow refreshes tools and the trash button removes the server." />

**Check after refresh:** existing permissions remain; new tools are disabled and missing enabled tools stay visible for review.

The local engine applies changes after **all unfinished runs complete**, including paused runs, human waits, and scheduled retries.

<details>
<summary>Pending changes and separately configured engines</summary>

Saved changes appear immediately in the app and survive restarts. Existing runs keep their admitted endpoint and credential. The managed engine applies changes automatically when idle; a manual restart is unnecessary.

For an engine configured elsewhere, its owner manages servers and credentials. Your local settings do not change that engine or switch the app away from it.

</details>

## Fix connection problems

<details>
<summary>No tools, unavailable tools, or validation errors</summary>

| What you see | What to check |
| --- | --- |
| No tools loaded | Use the actual MCP endpoint, check the server, and verify the optional token. An ordinary website URL is not an MCP endpoint. |
| A tool is unavailable in a block | Enable it in Settings and check that the server still advertises it. For an agent, also check that block's tool grant. |
| Connection changes are waiting | Finish or cancel unfinished runs, including human waits, before the engine can apply pending configuration. |
| Arguments or results fail validation | Check the selected tool's schema, unsupported saved fields, and its content or structured response format. |

</details>
