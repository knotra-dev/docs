---
title: Add an MCP server
description: Connect external tools in Settings, then use them in Tool and AI agent blocks.
---

Use an external MCP server to give a pipeline access to its tools. Save the server once in **Settings → MCP servers**, then choose tools in individual blocks.

Want an assistant to create pipelines and manage Knotra itself? Use [Control Knotra with MCP](/docs/guides/control-knotra). That is a separate connection from the external servers described here.

## Connect and choose allowed tools

1. Open the native desktop app and choose **Settings → MCP servers → Add server**.
2. Enter a useful **Server name** and its **MCP server URL**. Use the server's MCP endpoint over HTTPS, or HTTP on localhost. URL parameters, fragments, and credentials embedded in the URL are not supported.
3. If required, paste its bearer token into **Access token**, without the `Bearer` prefix.
4. Choose **Connect and load tools**. This discovers the tool catalog; it does not execute any tool.
5. Check the tools your pipelines may use, then choose **Save server**. New tools start disabled.

The server name, endpoint, catalog, and enabled tools survive app restarts. Tokens stay in the operating system credential store and are excluded from workspace backups. To edit a saved token, leave the field blank to retain it, enter a replacement, or select **Remove saved token**. If you change the server URL, explicitly re-enter or remove its token before connecting to the new address.

This setup supports HTTP MCP endpoints. Local command/stdio servers still require an engine profile. OAuth browser sign-in is not part of this form; use a server that accepts the optional bearer token or no authentication.

## Call a tool from a block

1. Add or select a **Tool** block in your pipeline.
2. Choose **MCP server**, then choose a tool by name. Only enabled tools are offered.
3. Read its description and enter its arguments. Simple object schemas have labeled form fields. Use the input mapping controls for values from previous blocks; complex custom arguments remain available in advanced configuration.
4. Connect its result to the next block or a workflow output.

For example, if a tool has a required `query` string, enter that query in its form or bind it to a previous block's text output. You do not need to write a server ID or tool ID.

When you select a tool, a new block uses the tool's advertised structured result schema when available. Tools without that schema use an array of content blocks. Custom output definitions are preserved; **Use tool response format** explicitly adopts the selected tool's format when needed. Check downstream bindings after changing an existing result's shape.

If a different tool does not accept fields saved for the old one, Knotra lists them and offers **Remove unsupported fields**. Review that list before removing them; compatible values are kept.

## Give an agent selected tools

Select an **AI agent** block and check the individual tools in its **MCP tools** list. The agent decides when to call those tools while following its instructions. Enabling a server in Settings does not grant every tool to every agent.

For example, enable a server's search and document tools in Settings, then grant only search to a research agent. Add document access to another agent only when its task needs it.

## Change a server safely

Use **Edit**, **Refresh tools**, or **Remove** beside its saved name. Refresh updates descriptions and schemas while retaining existing permissions. It does not enable newly discovered tools. Missing enabled tools stay visible for review.

Saved changes appear immediately in the app. The managed local engine applies connection changes automatically once every unfinished run completes, including paused runs, human waits, and scheduled retries. Existing runs keep their admitted endpoint and credential. You do not need to restart the engine manually. Pending changes survive reopening Knotra.

For an existing engine configured elsewhere, the engine owner manages its servers and credentials. Your saved local settings do not change that engine or switch the app away from it.

## Fix connection problems

| What you see | What to check |
| --- | --- |
| No tools loaded | Use the actual MCP endpoint, check the server, and verify the optional token. An ordinary website URL is not an MCP endpoint. |
| A tool is unavailable in a block | Enable it in Settings and check that the server still advertises it. For an agent, also check that block's tool grant. |
| Connection changes are waiting | Finish or cancel unfinished runs, including human waits, before the engine can apply the pending configuration. |
| Arguments or results fail validation | Check the selected tool's schema, unsupported saved fields, and its content or structured response format. |
